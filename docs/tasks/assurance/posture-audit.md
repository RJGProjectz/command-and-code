# Posture Audit - One-Command Workstation, Server & AD Config Posture

`scripts/powershell/Invoke-PostureAudit.ps1` is the easy-run umbrella over the CIS audit engine and
the Active Directory posture engine. It **auto-detects the host role** and, in a single read-only run,
reports current configuration posture for:

| Target | What it runs | Catalog |
| --- | --- | --- |
| Windows 10 / 11 workstation | CIS OS audit | `windows11-enterprise-v5.1.0.json` (shipped) |
| Windows Server (member / standalone) | CIS OS audit | `windows-server-2022-ms-v1.0.0.json` |
| Domain controller | CIS OS audit **+** AD posture | `windows-server-2022-dc-v1.0.0.json` + `adposture/ad-posture-v1.json` |

It is **read-only** in both `-TargetEnvironment Test` (default) and `Prod`: it reads the registry,
`secedit /export`, `auditpol /get` and (on a DC or with `-IncludeAd`) the directory. Nothing on the
host or in the directory is changed.

!!! tip "Where the report lands"
    `-OutputPath` defaults to the script's **own folder** (`$PSScriptRoot`), so the report is written
    wherever you run the script from - never a protected system path. There are no write-permission
    issues, and you can override with `-OutputPath D:\Evidence`. Use `-OutputPath ''` to skip files.

## Easy run - one command per target

```powershell
# Run from an ELEVATED PowerShell (5.1 or 7). Role is detected automatically.
.\Invoke-PostureAudit.ps1
```

```powershell
# Level 2 profile (includes all L1), report written next to the script
.\Invoke-PostureAudit.ps1 -Level L2
```

```powershell
# From a management workstation: AD posture only (no OS audit)
.\Invoke-PostureAudit.ps1 -SkipOs -IncludeAd -OutputPath D:\Evidence
```

The console prints every non-Pass check and a summary line
(`N checks (X OS, Y AD), pass/fail/error/na - score %`). Three report files are written by default:
`posture-<HOST>-<UTC>.json`, `.ndjson` (one line per check, SIEM-ready) and `.csv`.

## Output schema

Each result row is projected onto a unified shape so OS and AD checks merge cleanly:

| Field | Meaning |
| --- | --- |
| `Scope` | `OS` (CIS benchmark) or `AD` (directory posture) |
| `Id`, `Title`, `Category` | Recommendation id, title, and section/category |
| `Status` | `Pass` / `Fail` / `NotApplicable` / `Error` |
| `Expected`, `Actual` | Expectation(s) and the observed value |
| `Stig`, `Cis`, `BestPractice` | Per-framework verdict (AD rows; OS rows map `Cis` to the CIS result) |
| `Source`, `Detail` | Where the value came from, and any evaluation note |

The JSON report is schema `cc.posture.report/1` and records host, role, elevation, the OS catalog used
(`os`), and whether AD ran (`ad`).

## Operator guide - what each target needs and how to transfer it

The script and its engines are self-contained; copy the folder to the target and run. **Nothing needs
internet access at run time.**

1. **Copy** the `scripts/` tree to the target (or at minimum
   `scripts/powershell/Invoke-PostureAudit.ps1`, `scripts/powershell/CisAudit/`,
   `scripts/powershell/AdPosture/`, and `scripts/cis/catalogs/`). Keep the relative layout: the
   launcher resolves `..\cis\catalogs` from its own folder.
2. **Workstation / server:** open an **elevated** PowerShell (Run as administrator) so
   `secedit`/`auditpol` can read account, user-rights and audit-policy settings. Without elevation
   those checks report `Error` (registry-backed checks still resolve).
3. **Domain controller / management host:** install the RSAT **ActiveDirectory** module
   (`Add-WindowsCapability -Online -Name Rsat.ActiveDirectory.DS-LDS.Tools~~~~0.0.1.0` on Windows, or
   `Install-WindowsFeature RSAT-AD-PowerShell` on Server). On a DC, AD posture runs automatically;
   elsewhere add `-IncludeAd`.
4. **Run** `.\Invoke-PostureAudit.ps1`. Collect the `posture-*.json/.ndjson/.csv` files written beside
   the script (or at your `-OutputPath`).

!!! note "Server catalog provenance"
    The Windows Server catalogs are a **curated Level 1 core** authored from the free CIS Windows
    Server Benchmark PDF and the Microsoft Security Baseline - no Tenable `.audit` files required. They
    are generated by `tools/build_server_baseline_catalog.py` and are a subset, not the full benchmark.
    Expand them by adding entries and bumping the version. For a full per-item benchmark you can still
    build a Tenable-derived catalog with `tools/build_cis_catalog.py` (see
    [Windows Server CIS Audit](../hardening/windows-server-cis-audit-tool.md)).
